# `/wine/keywords` 아이콘·메뉴 뱃지 행 레이아웃 변경 계획

## 1. 범위와 기준

- 사용자 구현 요청에 따라 UI를 구현한다. 백엔드/API 계약은 변경하지 않는다.
- 2026-10-07 사용자 확인: 요청 shape는 그대로이고 고정 음식·직접 입력도 `menuNames`에 사용할 수 있다. AI 추천 목록에 제한하지 않고 선택한 모든 유효 음식명을 그대로 저장/전송한다. 이전 안내와 버튼 제한은 제거한다. 백엔드 fetch/수정은 이번 범위에 포함하지 않는다.
- 기존 메뉴 선택 뱃지의 색상·테두리·선택 표현을 유지한다.
- 카테고리별 박스·배경·그림자와 박스 내부 세로 배치를 제거하고 아이콘 옆에 뱃지를 배치한다.
- 고정 음식 선택을 위로, AI 추천을 아래로 이동한다. 직접 입력과 삭제 가능한 뱃지를 추가할 예정이다.
- 최신 사용자 요구를 레이아웃 기준으로 삼는다. 기존 `designs/enhanced_design_2.png`는 보라색 톤·타이포그래피만 참고한다. 실제 디자인 경로는 `design/`가 아닌 `designs/`이다.
- 참조: `web/GUIDE.md`, MCP의 shadcn-ui-mcp/style-implementation/rsc-rendering/rcc-rendering/storybook-authoring/data-flow-layering/bff-api-gateway.
- API 기준: `api/mysom-wine-pairing.md`의 recommend-menu, pairing 계약.

## 2. 목표 화면

```text
[홈]                      추천 메뉴

어떤 음식을 드시나요?
가장 가까운 카테고리를 선택해 주세요.

[아이콘] (소·양고기)
[아이콘] (돼지고기)
[아이콘] (닭·오리)

[아이콘] (생선)
[아이콘] (조개·갑각류)

[아이콘] (파스타·면)
[아이콘] (햄버거·면)
[아이콘] (밥·곡물)

[아이콘] (치즈·샤퀴테리)
[아이콘] (빵)

[아이콘] (디저트)

[아이콘] [찾는 음식이 없으면 직접 입력해주세요!] [추가]
         (입력한 음식1 ×) (입력한 음식2 ×)

────────────────────────────────────
어울리는 메뉴를 골라봤어요
선택한 와인을 기준으로 마이쏨이 추천했어요.
원하는 메뉴를 선택해 주세요.

[카테고리 아이콘] (추천 메뉴1) (추천 메뉴2)
                 (길어서 다음 줄로 넘어간 메뉴3)
[카테고리 아이콘] (추천 메뉴4)

                           (장바구니ⁿ)
[               와인 추천받기               ]
```

- 고정 메뉴 순서는 최신 요청에 적힌 11개 그대로 사용한다. 기존 고정 목록의 `채소`는 제외한다. AI가 반환한 채소 카테고리는 그대로 표시한다.
- 예시의 빈 줄은 육류/해산물/주식/치즈·빵/디저트 그룹 사이의 간격으로 해석한다. 그룹에 별도의 박스는 만들지 않는다.
- 고정 행은 아이콘 + 카테고리명 선택 뱃지 하나, AI 행은 아이콘 + 메뉴명 선택 뱃지 여러 개로 같은 정렬 규칙을 적용한다.
- AI 카테고리명은 시각적 중복을 피하도록 기본적으로 숨기고 접근성용 행 이름으로 제공한다. 아이콘에만 의미를 의존하지 않는다.
- 여러 개를 선택하는 기존 동작을 유지한다. 하나를 선택해도 다른 선택을 자동 해제하지 않는다.
- 추가 요구: AI 추천 위의 `N개 선택`은 제거하고 CTA 바로 위 오른쪽에 장바구니 플로팅 버튼과 선택 개수를 표시한다. 버튼을 누르면 공통 Dialog로 선택 목록을 확인/해제한다. 0개도 표시하고 빈 목록 안내를 제공한다. 고정·직접 입력·AI 선택을 합산하며 별도 개수 상태를 만들지 않는다.
- 장바구니는 CTA와 동일한 색상·반투명 배경·테두리·그림자를 사용하는 52px 정원(full-round)이며, 숫자는 아이콘 옆이 아닌 오른쪽 위 모서리의 오버레이 뱃지로 표시한다.
- 직접 입력의 시각적 `찾는 음식이 없어요` 라벨은 제거하고 같은 첫 행에 공통 TextInput을 배치한다. placeholder는 `찾는 음식이 없으면 직접 입력해주세요!`이며 스크린리더용 음식 이름 label은 유지한다.
- 최신 배치 변경: 뱃지 밖 아이콘 행 대신 뱃지 내부에 18px 아이콘을 표시한다. 고정/AI 뱃지는 기본 2열, 420px 이상 3열, 640px 이상 4열 grid로 배치한다. 직접 입력 뱃지도 작은 기타 아이콘을 포함한다. 이전 아이콘 행 레이아웃 설명보다 이 규칙을 우선한다.
- 2026-10-08 고정 메뉴는 grid 대신 4개 명시적 행(육류 3 / 해산물 2 / 주식 3 / 치즈·빵·디저트 3)으로 변경한다. 각 뱃지는 내용에 따른 가변 너비이며 아이콘은 안쪽에 유지한다. `햄버거·면`은 `햄버거·피자`로 변경한다. 좁은 화면에서는 뱃지 내부 간격/폰트만 작게 조정한다.
- AI 추천 메뉴도 가변 너비로 변경한다. `RecommendedMenuList`는 flex-wrap으로 자연스럽게 줄바꿈하며 공통 MenuNameBadge/SelectionBadge를 재사용한다. 일반 메뉴명은 한 줄로 표시하고 화면보다 긴 단일 메뉴명만 내부에서 줄바꿈한다. 선택 상태·순서·API 계약은 변경하지 않는다. Storybook에서 가변 너비와 긴 이름의 overflow를 검증한다.
- 직접 입력한 음식 뱃지는 아이콘 없이 이름과 삭제 버튼만 표시한다. 고정/AI 메뉴 아이콘과 입력 행의 아이콘은 유지한다.

## 3. 행·반응형·접근성 설계

- 공통 행은 `아이콘 슬롯 | 뱃지 영역` 2열이다. 아이콘은 줄어들지 않고, 뱃지 영역은 남은 폭에서 자연스럽게 줄바꿈한다.
- 다음 줄의 뱃지는 아이콘 아래가 아니라 첫 뱃지와 같은 시작점에 정렬한다. 가로 스크롤은 사용하지 않는다.
- 긴 이름은 뱃지 안에서 줄바꿈하고 모바일 폭을 넘지 않게 한다. 버튼 탭 영역은 모바일에서 최소 44px을 확보하되 현재 선택 스타일을 유지한다.
- 카테고리 박스 장식만 제거한다. 페이지의 밝은 보라색 톤, 선택 색상, 홈 이동, 하단 CTA와 safe-area 처리는 유지한다.
- 입력 중 모바일 키보드가 떠도 입력·추가·삭제와 하단 콘텐츠에 접근할 수 있도록 스크롤 및 CTA 겹침을 검증한다.
- 선택은 `aria-pressed`, 입력은 연결된 label, 삭제는 `음식명 삭제` 접근성 이름을 제공한다. 삭제 버튼을 선택 버튼 안에 중첩하지 않는다.

## 4. 직접 입력 동작안

- 입력할 때마다 뱃지를 생성하지 않는다. Enter 또는 `추가`로 확정하면 입력 아래에 뱃지를 추가한다.
- 한글 IME 조합 중 Enter는 확정 동작으로 처리하지 않는다.
- 앞뒤 공백 제거, 빈 입력 차단, 중복 입력 차단을 한다. AI 추천 이름과 정확히 같은 음식은 별도 중복 선택으로 세지 않는다.
- 빈 값·공백만 추가/Enter하면 조용히 무시하고 에러는 표시하지 않는다. 중복/길이 오류는 기존 안내를 유지한다.
- 추가된 음식은 기본 선택 상태이며 선택 해제·재선택할 수 있다. 삭제는 음식 목록과 선택 상태에서 함께 제거한다.
- 삭제 이후 입력 또는 인접 컨트롤로 초점을 복구한다. 빈 값·중복 안내는 입력 근처에서 제공한다.
- 직접 입력은 UI 보호를 위해 100자까지 허용한다. 기존 BFF의 이름당 200자·최대 50개 제한은 유지한다.

## 5. API 계약

사용자가 자유 입력 지원을 확인했다. recommend-menu는 `{ pairingWineIds }` → `{ recommendedMenus: [{ name, category }] }`, pairing은 `{ wineIds, menuNames }`로 shape를 유지한다. `menuNames`는 AI 추천 name뿐 아니라 고정 UI label과 직접 입력한 음식명을 허용한다. 새 endpoint/출처 필드를 추가하지 않는다.

- `생선`/`조개·갑각류` 등 UI label은 그대로 전달한다. API 응답 category enum은 변경하지 않는다.
- AI 응답을 사용자 입력으로 덮어쓰거나 Query cache에 직접 입력을 섞지 않는다.
- trim, 빈 값·중복 제거, 삭제된 입력/오래된 AI 선택 제외와 기존 BFF 입력 제한은 유지한다.
- 현재 로컬 백엔드 소스는 이전 검증 구현을 가지고 있으며 아직 fetch하지 않았다는 사용자 설명을 기록한다. 이번 검증은 UI·snapshot·요청 shape에 한정하고 실제 자유 입력 페어링 성공을 주장하지 않는다.

## 6. 구조·상태·데이터 흐름

- `wine/keywords/page.tsx`와 PageHeader는 Server Component로 유지한다.
- 기존 Client body 안에서 선택과 직접 입력을 관리하고 섹션별 UI를 분리한다. 새로운 전역 store는 만들지 않는다.
- AI 추천 원본은 기존 TanStack Query에 유지하고 별도 useState/Zustand에 복제하지 않는다.
- 입력 draft, 사용자 추가 음식, 선택 항목은 로컬 UI 상태다. 선택은 출처와 안정적인 식별자를 구분하고 최종 요청 중복 처리 규칙을 별도로 정한다.
- 브라우저 sessionStorage의 선택 wine snapshot 때문에 기존 hydration 후 Query 조회 흐름을 유지한다. 이번 레이아웃 변경으로 조회를 중복시키지 않는다.
- 데이터 경로는 Entity API → same-origin BFF → server-only 백엔드 호출을 유지한다. Query key와 자동 재시도 금지 정책도 유지한다.
- 기존 Entity 타입·BFF 검증·snapshot shape는 유지하고 선택한 음식명을 menuNames에 저장한다. 저장 성공 후 공통 경로 `/wine/chat`으로 replace 이동한다. 베타 인증 Middleware가 A는 통과시키고 B는 `/wine/recommend`로 redirect한다.
- AI 조회 중에도 고정 메뉴/직접 입력 UI는 유지한다. 로딩·오류·빈 결과는 AI 섹션에서만 표시한다. 스냅샷 없음은 기존 복귀 안내를 유지한다.
- 메뉴 스켈레톤도 새 아이콘+뱃지 행 구조로 맞추되 색상·pulse·reduced-motion 정책과 와인 스켈레톤은 유지한다.

## 7. 수정 예정 파일과 공통 UI

- 입력 스타일 보완: 공통 TextInput의 배경을 사각 래퍼에서 실제 input으로 옮긴다. 기본 흰색/disabled 회색은 유지하고 사용자 className 배경을 존중한다. 음식 입력은 공통 rounded-3xl을 사용한다. 베타/채팅 소비자와 공통 Storybook을 회귀 검증한다.

- `feature/menu-category-recommendation-result/ui/MenuCategoryRecommendationPage.tsx`: 섹션 순서, 선택·직접 입력 조합, CTA.
- `RecommendedMenuList.tsx`: 카테고리 카드 제거, 공통 행 사용. AI category/메뉴 순서는 기존 응답 순서 유지.
- `MenuNameBadge.tsx`: 기존 스타일을 공유 선택 뱃지로 추출/재사용하고 도메인 연결 역할만 유지.
- feature의 model/lib: UI 고정 카테고리 목록, 선택·추가·삭제·중복 처리 순수 함수.
- `shared/ui/atom` 또는 `molecule`: 기존 Button/TextInput을 우선 합성하고 필요 시 선택 뱃지·아이콘 행 공개 API 추가. feature에서 shadcn primitive를 직접 import하지 않는다.
- `shared/ui/molecule/skeleton-list.tsx`: 다른 화면에 영향 없이 메뉴 행용 variant 확장 검토.
- 관련 Storybook, 단위 테스트, `docs/wine-keywords.md`: 구현 완료 후 변경 사항 반영.
- API 문서는 사용자 확인에 따라 입력 의미만 갱신하고 HTTP/DTO shape는 변경하지 않는다.

## 8. 구현 순서와 완료 기준

1. AI 허용 목록 제한 및 준비 중 안내를 제거하고 고정·직접 입력·AI 메뉴 선택 모두 허용한다.
2. 공통 뱃지·행과 스토리를 준비하고 고정 메뉴 → 직접 입력 → 구분선 → AI 메뉴 순서로 재배치한다.
3. 직접 입력 추가/삭제와 선택 상태를 연결하고 기존 menuNames shape로 snapshot·CTA·BFF를 유지한다.
4. AI 로딩·실패·빈 결과·재시도와 새 행 스켈레톤을 맞춘다.
5. 단위/Storybook/모바일 검증 후 개발 문서를 갱신한다. 커밋·푸시는 별도 요청 시 수행한다.

검증 범위:

- 320/390/430px 및 데스크톱: 긴 메뉴명·여러 뱃지 줄바꿈·아이콘 정렬·가로 넘침·CTA 겹침.
- 고정 순서, AI 그룹 순서, 선택/해제, 복수 선택, 입력 추가/삭제/중복/공백/IME/키보드 접근성.
- AI 조회 중 고정 UI 유지, 오류/빈 결과, 스냅샷 없음, 재시도 후 오래된 AI 선택 제외.
